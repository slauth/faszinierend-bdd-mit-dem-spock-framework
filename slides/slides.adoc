== Was ist das Spock Framework? 🖖

[quote,'https://spockframework.org/[spockframework.org], übersetzt']
„Spock ist ein +
*Test-*, *Spezifikations-* und **Mocking-**Framework +
für JVM-Entwickler, +
das Wert auf *Lesbarkeit* und *Klarheit* legt.“

[.notes]
--
* *Lesbarkeit* und *Klarheit*
   ** werden _immer wichtiger_, da wir mehr Code lesen
* Überleitung: *Test* und *Mocking* = JUnit

== Wie bekomme ich das *lesbarer* und *klarer* hin? 🤔

=== Behavior Driven Development (BDD) 🗣️

*Idee:* gewünschtes Verhalten innerhalb fester Strukturen +
in der Sprache des Fachbereichs beschreiben

[%step]
[source,gherkin]
----
Feature: Shopping Cart Discounts

  Scenario Outline: Apply discount based on membership date and order value
    Given a customer that is member since <member_since>
    And an order of $<total> EUR value
    When they place the order
    Then they get $<expected_discount> EUR discount

    Examples:

      | member_since |  total | expected_discount |
      |   2026-12-09 |  99.00 |              0.00 |
      |   2026-12-09 | 100.00 |              5.00 |
      |   2025-12-09 |  99.00 |              0.00 |
      |   2024-12-09 |  99.00 |              9.90 |
      |   2024-12-09 | 100.00 |             15.00 |
----

[.notes]
--
* Nähe zu Domain Driven Design (DDD)
* aus TDD heraus entstanden
    ** „Test“ lenkt den Blick zu stark aufs Prüfen
    ** „Behaviour“ auf das gewünschte Verhalten
* `Given` = Ausgangslage, `When` = Aktion, `Then` = erwartetes Ergebnis
* erfordert aber extra „Glue Code“ / ist nicht direkt ausführbar
* Überleitung: unser JUnit-Test macht nichts anderes …
--

=== Spock: Groovy *Power Assertions* 💡

[source,text]
----
[ERROR] de.slauth.shop.discount.DiscountCalculatorSpec.member since 2026-12-09, order of
100.00 EUR gets 5.00 EUR discount -- Time elapsed: 0.144 s <<< FAILURE!

Condition not satisfied:

calculator.discountFor(customer, order) == expected
|          |           |         |      |  |
|          0.00        |         |      |  5.00
|                      |         |      false
|                      |         Order[total=100.00]
|                      Customer[memberSince=2026-12-09]
<de.slauth.shop.discount.DiscountCalculator@1f992a3a>
----

[.notes]
--
* Power Assertions: ein einfaches `==` zeigt jeden Zwischenwert
* Kein Debugger, kein AssertJ/Hamcrest-DSL nötig

=== Browser Tests (Spock + Geb) 🖥️

[.small]#https://groovy.apache.org/geb#

[source,groovy]
----
class HomepageSpec extends GebSpec {

    void "can access settings from homepage"() {
        given: "I'm at the home page"
            to HomePage

        when: "I open the nav and click on the first link"
            nav.open()
            nav.links[0].click()

        then: "I'm at the settings page"
            at SettingsPage
    }
}

class HomePage extends Page {

    static at = { title.startsWith("Welcome") }

    static content = {
        nav { module(NavModule) }
    }

    static url = "/"
}
----

[.notes]
--
* Geb baut auf Spock auf
* Page Object Pattern

== 3 Dinge zum Mitnehmen 💡

[%step]
. *lesbar & klar* +
  `given`-`when`-`then` als echte Struktur, +
  `where`-Tabellen direkt am Test
. *direkt ausführbare* Spezifikationen, +
  die sowohl das Business als auch ein KI-Agent versteht
. *aussagekräftige* Power Assertions +
  erklären detailliert jeden Fehlschlag
